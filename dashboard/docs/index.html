Sub-score computation

Each parameter family aggregates its members through weighted summation after normalization. The within-family weights wj are renormalized to sum to 1 after filtering unavailable parameters — this means the model degrades gracefully when an API is unreachable.

def compute_subscore(df, weights):
    """Normalize each parameter to [0,1], then weight-sum → sub-score [0,100]."""
    cols = [c for c in weights.keys() if c in df.columns]
    if not cols:
        return pd.Series(50.0, index=df.index)  # graceful fallback

    scaler = MinMaxScaler()
    normed = pd.DataFrame(scaler.fit_transform(df[cols].fillna(0)),
                          columns=cols, index=df.index)

    # Invert distance-based columns (closer = better)
    for col in ["estuary_dist_km", "beach_dist_km"]:
        if col in normed.columns:
            normed[col] = 1 - normed[col]

    w = np.array([weights[c] for c in cols])
    w = w / w.sum()  # renormalize after filtering
    return (normed[cols] @ w) * 100

The composite is then computed as the hard-gate-filtered, weighted sum:

def compute_composite_score(candidates_df):
    """Full scoring pipeline — returns ranked GeoDataFrame."""
    df = apply_hard_gates(candidates_df.copy())  # removes V>3.0, W>50m, private land

    df["generation_score"]  = compute_subscore(df, GENERATION_WEIGHTS)
    df["flow_score"]        = compute_subscore(df, FLOW_WEIGHTS)
    df["impact_score"]      = compute_subscore(df, IMPACT_WEIGHTS)
    df["feasibility_score"] = compute_subscore(df, FEASIBILITY_WEIGHTS)

    df["composite_score"] = (
        0.30 * df["generation_score"]
      + 0.25 * df["flow_score"]
      + 0.30 * df["impact_score"]
      + 0.15 * df["feasibility_score"]
    )
    return df.sort_values("composite_score", ascending=False)

§2 — Hydraulics

Manning's Velocity Equation

Flow velocity at each candidate site is estimated via Manning's open-channel equation, the standard approach in computational hydrology since 1891:

Roughness coefficients n

Manning's roughness coefficient characterizes channel bed friction. Values from Chow (1959), Open-Channel Hydraulics:

MANNING_N = {
    "clean_straight":    0.030,  # gravel/sand, no vegetation
    "winding_some_pool": 0.040,  # typical urban creek (Ellerbe)
    "sluggish_weedy":    0.070,  # heavy vegetation, slow flow
    "urban_concrete":    0.015,  # engineered concrete channel
}

Continuity cross-check

A second velocity estimate is derived from the continuity equation using USGS-measured discharge:

The final velocity is the geometric mean of both estimates, hedging against DEM slope noise and channel geometry assumptions:

def compute_flow_velocity(row, dem_array, dem_transform, gauge_stats):
    # Channel geometry (rectangular approximation)
    W = row.get("channel_width_m", 5.0)
    D = 0.3 * W  # bankfull depth ≈ 30% of width
    A_cross = W * D
    P_wet = W + 2 * D
    R_h = A_cross / P_wet  # hydraulic radius

    # DEM slope over 100m reach
    slope = compute_local_slope(row, dem_array, dem_transform, reach=100)
    slope = max(slope, 0.0001)  # clamp to avoid zero

    n = 0.040  # winding_some_pool default
    V_manning = (1/n) * R_h**(2/3) * slope**(0.5)

    # Continuity cross-check
    Q_cms = gauge_stats["mean_q_cfs"] * 0.0283168  # cfs → m³/s
    V_cont = Q_cms / max(A_cross, 0.01)

    # Geometric mean hedges both estimates
    return math.sqrt(V_manning * max(V_cont, 0.01))

§3 — Diminishing returns

Upstream Occlusion Model

The central algorithmic insight: a net upstream reduces the value of all downstream nets on the same waterway. Each net catches η = 65% of debris passing through it. The trash reaching a downstream position after k upstream nets is:

Catch efficiency model

Trash reaching downstream positions (interactive)
0.65
Each upstream net compounds the passthrough multiplicatively. At η=0.65, a 3rd net on the same stream sees only 4.3% of original trash — making it almost always better to place that net on a different stream.

Only the generation sub-score is discounted. Flow, impact, and feasibility are intrinsic to the location — they don't change based on upstream nets.

Greedy selection algorithm

The algorithm greedily picks the highest-scoring candidate, then discounts all downstream positions on the same stream, then re-sorts and picks again:

while |selected| < target and remaining ≠ ∅:
    remaining.sort_by(composite, descending)
    best ← remaining.pop_first()
    selected.add(best)

    // Discount all DOWNSTREAM candidates on SAME stream
    k ← upstream_nets[best.stream] += 1
    for c in remaining where c.stream == best.stream
                       and c.coord_idx > best.coord_idx:
        passthrough ← (1 − η)k
        c.gen ← c.raw_gen × passthrough
        c.composite ← 0.30·c.gen + 0.25·c.flow + 0.30·c.impact + 0.15·c.feas
Why greedy beats static percentile: A static top-N% cut would keep two candidates on the same stream — both scored before occlusion. The greedy approach recognizes that #2's value drops by 65% after #1 is placed. The re-sort after each placement captures this dynamic revaluation.

Culvert portal detection

Underground waterway segments are detected from OpenStreetMap tags and excluded from candidate placement. Their entrance and exit coordinates are injected as candidates only when the parent waterway is a river, canal, or stream — culverts under drains or ditches are not real chokepoints and would otherwise dominate the top-N because so many road crossings are tagged this way.

// OSM tags that indicate underground segments
const underground = tags.tunnel === 'yes'
    || tags.tunnel === 'culvert'
    || tags.tunnel === 'building_passage'
    || tags.covered === 'yes'
    || tags.layer === '-1'
    || tags.layer === '-2';

const PORTAL_PARENTS = new Set(['river', 'canal', 'stream']);

if (underground && PORTAL_PARENTS.has(ww)) {
    // Don't place nets ON underground segments — but mark entrance and exit
    // as portals, carrying the parent waterway type so the bonus can scale.
    portals.push({ lon: coords[0],   lat: coords[0],   type: 'entrance', parentWw: ww });
    portals.push({ lon: coords[N], lat: coords[N], type: 'exit',     parentWw: ww });
}

Portal candidates use a deliberately moderate catchment assumption — upstreamFrac = 0.6 for entrances and 0.4 for exits, with order = 2. The previous extreme values (0.95 / 0.05 with order = 3) inflated the four sub-scores so much that culverts dominated the top 20 even before the bonus was applied. The bonus itself is also scaled by parent type and added after the four sub-scores combine:

Parent waterwayComposite bonusRationale
river+5Real catchment, real flow — culvert is genuinely the last access point
canal+3Engineered conveyance, predictable trash load
stream+1Moderate flow; still a meaningful choke point
drain / ditch—No portal candidate generated at all (skipped at parse time)

Waterway-type composite penalty

The four sub-scores (Generation, Flow, Impact, Feasibility) draw on parameters that are largely insensitive to whether a line in OSM is a real river or a 30 m drainage dash. Without an explicit type signal, a randomly-good ditch could leapfrog an actually-important stream. To prevent that, surface positions take a small composite penalty based on the OSM waterway tag:

WaterwayComposite penalty
ditch−6
drain−3
stream / canal / river0

The penalty is preserved through the greedy occlusion re-rank — otherwise an occluded ditch could silently re-rise above an unoccluded stream just because its raw generation was discounted less.

Length & intermittency gates

Tiny disconnected dashes in OSM (a 40 m unnamed ditch in a field) produce noise but no value. We drop them at parse time using a per-type minimum length:

WaterwayMinimum length
river / canal50 m
stream120 m
drain / ditch250 m

Length is computed by summing haversine distances along the OSM way's geometry. We additionally drop ways tagged intermittent=yes, except for rivers — intermittent rivers in arid regions still carry a year's worth of accumulated debris during storms.

Per-fetch quality bar

Both the initial city fetch and every pan-autoload fetch run their results through the same applyQualityBar filter so panning around can never sneak in low-priority short ditches or stormdrain culverts that the initial criteria would have trimmed:

function applyQualityBar(streams, opts = {}) {
    const maxStreams  = opts.maxStreams  ?? 25;
    const maxCulverts = opts.maxCulverts ?? Math.max(2, Math.floor(maxStreams * 0.15));
    // Sort: surface first, then by length (longer = more nodes)
    streams.sort((a, b) =>
        (a.underground ? 1 : 0) - (b.underground ? 1 : 0)
        || (b.coords.length - a.coords.length));
    const surface  = streams.filter(s => !s.underground).slice(0, maxStreams);
    const culverts = streams.filter(s =>  s.underground).slice(0, maxCulverts);
    return [...surface, ...culverts];
}

For a population > 1M city the slice is 25 surface + at most 3 underground per fetch. Cumulative pan-autoload merges go through streamKeySet to dedupe ways that have already been added, so the cap applies per fetch, not as a hard global limit.

Traffic capacity per waterway

function waterwayCapacity(stream) {
    const n = stream.coords.length;
    if (stream.waterway === 'canal') return Math.max(5, Math.floor(n/3)); // boat traffic
    return Math.max(8, Math.floor(n/2));  // rivers/streams

§5 — Robustness

Monte Carlo Sensitivity Analysis

Dirichlet perturbation

Weight vectors must sum to 1 (convex combination). The Dirichlet distribution is the natural choice for sampling from a simplex. We use α = 10 × baseline weights to control perturbation magnitude:

def sensitivity_analysis(candidates_df, n_perturbations=50):
    baseline = compute_composite_score(candidates_df)
    top5_counts = pd.Series(0, index=baseline.index)

    for _ in range(n_perturbations):
        alpha = np.array([0.30, 0.25, 0.30, 0.15]) * 10
        perturbed = np.random.dirichlet(alpha)  # samples from simplex

        df = baseline.copy()
        df["composite_score"] = (
            perturbed[0] * df["generation_score"]
          + perturbed[1] * df["flow_score"]
          + perturbed[2] * df["impact_score"]
          + perturbed[3] * df["feasibility_score"]
        )
        top5 = df.nlargest(5, "composite_score").index
        top5_counts[top5] += 1

    baseline["robustness_pct"] = top5_counts / n_perturbations * 100
    return baseline

This runtime robustness_pct is a strict top-5 membership metric for each served candidate. The paper-validation receipt is separate: scripts/validate_paper.py --dirichlet measures whether the baseline top 10 stay inside the top 25 across 10,000 seeded draws.

§6 — Computational hydrology

DEM Hydrological Conditioning Pipeline

Raw elevation data from USGS 3DEP (10m resolution) must be hydrologically conditioned before flow routing. The pipeline uses pysheds — an in-memory NumPy-based hydrology library:

# 1. Fetch DEM raster
dem = py3dep.get_map("DEM", bbox, resolution=10)

# 2. Hydrological conditioning
grid = Grid.from_raster(dem)
pit_filled    = grid.fill_pits(dem)              # remove single-cell sinks
flooded       = grid.fill_depressions(pit_filled) # fill multi-cell depressions
inflated      = grid.resolve_flats(flooded)       # assign gradient to flat areas
flow_dir      = grid.flowdir(inflated)            # D8: each cell → 1 of 8 neighbors
accumulation  = grid.accumulation(flow_dir)       # count upstream cells per cell

# 3. Extract stream network (cells with >500 upstream cells)
streams = grid.extract_river_network(flow_dir, accumulation, threshold=500)
# 500 cells × 10m × 10m = 0.05 km² minimum catchment area

# 4. Generate candidate points along stream network
candidates = extract_candidates(streams, spacing=200)  # 200m apart

The D8 algorithm assigns each cell exactly one of 8 cardinal/diagonal flow directions based on steepest descent. This is the standard approach in computational hydrology (O'Callaghan & Mark, 1984).

Multi-source channel resolution: Channels finer than the 10 m DEM raster are resolved from NHD and OSM waterway geometry, so sub-10 m streams are still captured.
